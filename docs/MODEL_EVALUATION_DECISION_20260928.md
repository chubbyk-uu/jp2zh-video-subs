- **原始 ASR 传播探针**：新增 `--source-mode raw-asr`，20 段 GalTransl／ASMR Q4 GPU 对照全部完成，共 266 条窗口译文位置／192 条重点对照位置；这些计数只是阅读工作量，不是正确条数。保留原始 ASR 文本，不把它标为真值。它不是重跑四部音频的全流程测试。

复核页面分别显示原始输入、校对目标、参考中文及匿名译文，所有 133 条均检查。背景不加入重点分母，但关键否定、回复角色变化和删除纳入选型风险，不能因“不评分”而漏报。匿名列只用于减少标签干扰，评审者已知道历史表现，不能称为独立人工日语盲审。

## 结构、运行成本与验证

20 段原始输入两组逐条相同，参考文件摘要复核通过，ID、源时间和重点集合未改变。GalTransl 共 20 次实际模型请求，每次包含完整窗口，非翻译缓存命中；ASMR JSON 全部合法，无重复／未知／缺失 ID、并条或时间声明错误，无 token 上限退出。ASMR 有 3 个显式 `null`：1 个重点及 2 个背景，合法结构不掩盖内容删除。

新增 11 段校对输入同样逐条配对，GalTransl 11 次完整窗口请求，ASMR 有 2 个显式 `null`，与本批原始输入对应位置相同。生产模型默认、全片分段和提示行为均未改动。

| 对照 | GalTransl 推理合计 | ASMR Q4 推理合计 |
| --- | ---: | ---: |
| 20 段原始 ASR 输入 | 8.7 秒 | 112.8 秒 |
| 新增 11 段校对输入 | 5.4 秒 | 72.2 秒 |

均使用 RTX 5080、GPU layers=-1，不混入先前 CPU 实验。20 段加载分别约 20.6／0.8 秒，存储路径和缓存不同，单列而非用于模型加载排名。ASMR 输出带 ID／时间的 JSON，GalTransl 为逐行中文，解码、输出量及协议也不同；本次约 13 倍的推理差距是**当前两套实验实现的单次成本**，不能写成纯权重差距或所有硬件／生产实现都如此。没有持续测量独立显存峰值。

代码新增原稿输入模式、证据标识及复核页双日文展示，拒绝缺原稿、输入模式或背景不一致。全套测试 **577 passed**，两个已有 librosa 警告；静态与差异检查通过。参考和原稿均保留在忽略目录，未改原始视频／历史字幕。

## 端到端观看盲测：jaykwok

上述文本对照的参考由基线稿推断、选样排除了文字无法确定的片段，结构上难以区分候选 ASR。因此改为按实际观看体验评判：用户不懂日文，只看中文字幕是否配合画面、前后连贯、有无胡话或漏字幕。

- 两臂均为四部完整视频的生产流水线，仅 ASR 不同：默认 anime 与仅替换 Qwen 权重的 jaykwok（`--asr qwen`），翻译都用默认 GalTransl。
- 按 20 秒窗口比较两版中文，相似度低于 0.6 且文字不少于 8 字的窗口视为差异窗口：共 1,734 个窗口（含无对白窗口）中 942 个差异明显，说明两者输出确有可感知的不同。
- 从差异窗口中固定种子随机抽 30 段（每视频 7–8 段，同视频不取相邻窗口），每段前留 5 秒、后留 3 秒上下文，约 28 秒；每段 A/B 位置随机，映射与页面分开保存，投票后才揭盲。

| 结果 | 次数 |
| --- | ---: |
| 默认 anime 更好懂 | 14 |
| jaykwok 更好懂 | 9 |
| 差不多 | 7 |

按视频的 jaykwok 胜／负／平：V01 5／3／0，V02 0／6／2，V03 2／1／4，V04 2／4／1。双侧符号检验 p=0.40，不能说默认显著更好，但候选没有显示任何优势，且在 V02 全负、不稳定。A、B 位置分别被选 11／12 次，无位置偏好。**结论：jaykwok 不替换默认 ASR，关闭此候选线。**

局限：单一评审、30 段；两版都通顺但含义不同的错误无法由不懂日文的观众识别，此测试衡量的是观看体验而非 ASR 真实准确率。

工具：[ab_blind_test.py](../scripts/ab_blind_test.py)（`pipeline`／`asmr`／`build`／`score` 子命令）；页面、片段、揭盲映射和投票只放在被 Git 忽略的本地目录。实验为流水线子进程单独指定 `NUMBA_CACHE_DIR`：共享的旧 Numba 缓存曾使音频预处理段错误，清除 `/tmp/numba_cache` 后全套测试恢复正常。

## 端到端观看盲测：ASMR 翻译

同一默认 anime ASR 日文输出，只换翻译：默认 GalTransl 对 ASMR Q4_K_M。ASMR 按连续字幕窗口翻译（每窗口最多 20 条，不跨 10 秒以上停顿），沿用实验协议的提示、JSON 输出及贪心解码；时间只取源字幕 ID，保留模型的合并与显式删除。选样、剪辑和揭盲方法同上：1,734 个窗口中 752 个差异明显，随机抽 30 段。

| 结果 | 次数 |
| --- | ---: |
| GalTransl 更好懂 | 10 |
| ASMR 更好懂 | 10 |
| 差不多 | 10 |

按视频的 ASMR 胜／负／平：V01 3／3／2，V02 3／4／1，V03 2／1／4，V04 2／2／3；p=1.0，A、B 各被选 10 次。观看体验完全持平，而 ASMR 在四部全片（2,559 条源字幕）上显式删除 123 条、拆到单条仍失败 27 条，无 grammar 请求因重复失控触及 token 上限 79 次（含拆分后的子窗口）。**结论：不替换 GalTransl，也不作为可选慢速模式接入。**

### ASMR 速度诊断（供以后类似 GGUF 候选参考）

- 瓶颈是 llama.cpp 的 JSON grammar 采样，占用单核 CPU，GPU 利用率仅约 30%：同一窗口 GPU 生成约 126–130 tok/s，但带 grammar 的实际速度只有 33 tok/s；flash attention 无影响。
- 去掉 grammar、改为 Python 校验：此前 20 个评估窗口的输出与 grammar 版**逐字节相同**，全部合法，耗时 112.8→32.7 秒（约 3.4 倍）。
- 全片上仍有两类不合法输出：单条字幕窗口常直接输出纯文本而非 JSON（改用 grammar 重试可恢复）；重复失控写满 token 上限（grammar 只屏蔽 token，重试会重放同一循环，应直接拆窗口）。按每条 100＋100 设 token 上限，防止单窗口耗尽 2,048 token。
- 优化后四部全片 ASMR 翻译约 29 分钟（旧方式估计 2 小时以上）；同样内容 GalTransl 只需几分钟。
