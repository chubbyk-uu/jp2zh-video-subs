# 字幕质量评估改进与模型对照测试计划

更新日期：2026-09-28。状态：本轮选型结束，三款候选均不接入，默认 anime ASR 与 GalTransl 不变。以下保留原计划，不代表仍有待执行任务。

实施记录：[首轮试样与评估器改进](MODEL_EVALUATION_PROGRESS_20260928.md)、[困难集扩展历史](MODEL_EVALUATION_EXPANSION_20260928.md)、[实用对照与最终观看盲测结论](MODEL_EVALUATION_DECISION_20260928.md)。已完成 20 段普通／困难混合对照，以及基于四部全片输出的两轮观看盲测；未扩展到 40–60 段。Windows CLI／GUI／绿色版仍未验证，不再列为本轮待执行任务。候选权重与私有实验材料已删除；进一步选型按用户决定暂停。

本轮先优化质量评估，再测试两款 ASR 和一款日中翻译模型。先完成 Linux 下的评估和对照实验，Windows CLI、GUI 与绿色版程序验证放在最后。计划中的步骤与实施结果分开记录；当前默认模型的切换需有测试依据，release 另行安排。

## 1. 范围与顺序

1. 盘点四个视频、现有字幕和评估证据，建立可复现的样本清单。
2. 修正评估方法，分开衡量识别、翻译、时间轴、结构和运行成本。
3. 用人为构造的错误和上下文校对的真实样本检查评估方法；没有听音真值的项目明确保留未验证状态。
4. 通过评估验收后，开展 ASR 和翻译模型对照测试。
5. 根据结果决定是否采用候选，完成必要的 Linux CLI/GUI 适配。
6. 最后验证 Windows CLI、GUI 和绿色版程序；提交、推送、发布另行安排。

素材仍使用用户指定本地目录中的四个视频，不另换公开测试集代替。公开文档和报告用 V01–V04 标识；实际路径、文件名、片段和字幕留在被 Git 忽略的本地实验目录。不上传视频或字幕给外部评审 API。四个视频的结果只代表该样本范围，不能直接推广为所有动漫、成人对白或 ASMR 的质量排名。

当前没有能听懂日语的人工核对者，也没有已验证可用的本会话直接听音能力。因此本轮采用“现有 ASR 初稿 → 助手按上下文校对日文 → 制作中文参考译文”，不以补齐人工听写真值为启动前提。以下涉及听音真值的指标均为条件性能力，不代表本轮已经能够测量。

## 2. 实施前评估审计的问题

以下问题来自实施前的代码审计，而不是新模型测试结论；当前修正进度见实施记录：

| 当前做法 | 为什么可能误判 | 计划修正 |
| --- | --- | --- |
| `subtitle_benchmark.py` 以 anime 字幕为锚点，由至少一个 Qwen 输出确认“共识” | 模型可能共同识别错误；锚点遗漏的内容难以进入评估 | 共识仅用于找分歧、安排复核，不作为真实准确率或选型依据 |
| 将 anime 独有片段直接称为弱语音 | 独有输出也可能是幻觉 | 改称“单源候选片段”，听音确认后再分类 |
| 读音二元组集合重叠率、默认阈值 0.34、前后各 4 秒窗口 | 丢失重复次数和部分顺序，不惩罚额外生成；可能借邻句命中，掩盖错词和漂移 | 使用序列编辑距离和受约束的句组对应；额外文本计插入，时间误差单独统计 |
| 读音归一化删除长音符，跳过不足 3 字的短句 | 可掩盖词义差异，并漏评有意义的短回答 | 显式记录归一化规则；短句纳入，读音指标仅作补充 |
| VAD 覆盖和字幕内部空窗用于提示漏识别 | VAD 不是语言真值，可能把呼吸、音乐当语音；全空输出及首尾空窗需专门覆盖 | 与音频全长核对；区分疑似缺口、已确认漏句、非言语声音 |
| 翻译主要检查假名残留、疑似非简体字和相邻重复 | 无法判定否定、人物关系、主客体、程度和语境是否翻错 | 加入基于源文、上下文和错误证据的语义评审 |
| 相邻重复检查按日中字幕位置 `zip` | 删条、并条后可能错配，较长一侧会被截断 | 以明确的源 cue ID / 句组映射对应，并报告缺失与多余项 |
| 历史实验复用只检查输出文件存在且非空 | 更换模型、参数或评估器后可能沿用旧结果 | 使用输入、模型版本、参数、运行环境和评估器版本组成缓存标识 |

相关实现：[共识评估](../scripts/subtitle_benchmark.py)、[质量报告](../scripts/quality_report.py)、[历史 Qwen 参数实验](../scripts/run_qwen_stage6_benchmark.py)。历史报告仍可作为排查线索，但其中共识召回、VAD 覆盖、字幕条数不能解释为真实识别准确率。

## 3. 第一阶段：样本与参考证据

### 3.1 固定素材和实验清单

- 为 V01–V04 记录文件摘要、时长、音轨、采样率、声道和已有字幕版本；确认没有把不同剪辑或偏移版本混用。
- 记录当前 anime、Qwen、GalTransl 的模型文件摘要、配置、提示词、切片、VAD、对齐器、后处理和运行环境，作为不可覆盖的基线。
- 样本最终按原始视频的时间段定位。按用户最新建议，可从历史字幕反查完整日常或易错段落以提高效率；字幕只提供定位线索，不作为原音真值。这种抽样会忽略历史漏句，不宣称覆盖全片或随机代表性。
- 保存随机种子和抽样规则；开发集与盲测集按场景分离，并留出上下文间隔，防止相邻片段泄漏。

### 3.2 将参考字幕分成三类

| 证据等级 | 允许用途 | 不允许用途 |
| --- | --- | --- |
| 对照原音核对并记录确认者、版本的日文及边界 | ASR 字错率、漏句、幻觉与时间轴评估 | 将无法听清的部分强行补成确定答案 |
| 仅按文本上下文审校的日文或中文 | 待确认候选、术语线索、相对于该日文输入的翻译检查 | 当作听音确认的 ASR 真值 |
| 原始模型输出或多模型一致结果 | 分歧定位、抽样、辅助复核 | 仅凭一致就认定正确 |

已有文件名中的 `reviewed` 不等于经过听音核对。先查审校记录；未记录原音核对的内容按第二类处理。中文参考允许多种正确表达，不以逐字匹配判定翻译好坏。

听不清、多人重叠或有合理歧义的片段记录备选和不确定区间，报告未评分数量及占比，不能悄悄排除难例。若暂时缺少可靠听音标注，可继续实现检查器和整理待核对样本，但真实 CER 和模型胜负必须标为待确认。

### 3.3 抽样与上下文校对工作量

- 先从四部视频各取 2–3 段，共 8–12 段试样，检查初稿、上下文和可确定修正的比例；这一批用于开发和调试，不用于最终排名。
- 最新工作量：先形成总计约 20 段普通／困难混合对话，复用已有可靠参考与音频，按历史字幕反查补充，不再为凑 40–60 段反复扩大抽样。优先保留完整问答及连续多条前后文；达到这批实用对照后即给出接入建议，不继续等待大规模语料。
- 扩展前固定开发/保留测试集划分；测试集不用于调参数，参考稿在查看候选输出前冻结。具体段数与比例根据试样的有效内容确定，不能将试样反复用于最终排名。
- 选择否定、条件、人物指代、主客体、使役受益、成人场景词义等易错对白，也按用户最新补充纳入日常对白，不要求每段都困难。两套基线分歧可作为风险线索，不自动确定哪稿正确；既有开发样本可用于实用回归，但不能包装成新盲测。
- 后续用户补充：方言能译准最好，但不苛求。方言口吻、地方词尾和细节准确度作为加分／专项观察，不作为主要选型依据或单独淘汰条件；重点仍是关键意思、主体、否定、动作对象和上下文。关键含义拿不准仍须换选，不为了还原方言腔而猜写标准答案。
- 低音量、耳语、背景音乐和重叠说话等声学标签需原音证据；仅有文本不能认定。对白须能确定关键含义，无法确定就换选。普通／困难可以组成实用对照集，必须披露构成、旧样本复用和证据限制，不作独立盲测排名。
- 普通集与刻意挑选的困难集分开报告，不能把困难集错误率冒充全片错误率。多模型分歧可补充困难集，但不能替代独立抽样。
- 复核页面或清单提供原音定位、上下文、匿名 A/B 输出、错误类型和证据；隐藏模型名称，交换展示顺序。争议项二次核对；不能复核的项目保留“不确定”。

### 3.4 ASR 初稿、日文校对与参考翻译

1. 使用现有不同体系的 ASR（anime 与 Qwen）分别生成初稿，保留原始文字、时间和配置。不使用本轮待测的微调模型生成参考答案；同系列模型不能视为多个独立证人。
2. 助手阅读整段及前后文，对比初稿，检查错词、断句、人名、指代、否定、术语和前后矛盾。此步骤是文本上下文校对，不宣称直接听过原音。
3. 每处修订分级：**高把握修正**（上下文和不同转写相互支持）、**可能修正**（合理但缺少原音确认）、**无法判断**（保留原文与多个候选，不强选答案）。高把握仍属于文本证据，不升级为听音真值。
4. 保存片段 ID、原视频时间、各 ASR 原稿、校对稿、修改位置、修改理由、把握等级及未决项。仅“更通顺”或“更符合剧情”不足以支持改写，禁止凭剧情补出无证据的对白。
5. 基于校对稿制作简体中文参考译文，传递日文的不确定标记，必要时提供不同解释对应的译法。允许多种正确中文表达，不以字面一致率评判翻译。
6. 冻结参考版本再比较候选。如果候选暴露参考稿问题，单独记录争议，不能直接改成候选答案后给该候选加分；如需修订，保留版本并对所有对照统一重评。

实施期间新增的用户决定：关键含义实在拿不准的片段，放弃作为标准样本，从同一视频重新选择完整对话。标准样本的重点区间不得包含“可能修正”或“无法判断”的关键语句；重点区间没有有效对白也需换选。原片段及弃用理由留在开发记录中，不能通过猜测消除不确定性。前后文中不影响重点对话的未决内容仅作背景线索，不参与标准答案评分。换选后的参考仍是上下文校对稿，不升级为听音真值；这批精选对话的成绩只代表精选样本。

这套产物称为“上下文校对参考稿”，不是“人工听写标准答案”。它适合评估相对于固定日文的翻译质量、结构问题和可追溯的文本风险；无法排除把原话错听成另一句同样通顺的话。用于生成初稿的基线也可能因此得到偏好，所以不能凭与参考稿接近就判定基线或候选的 ASR 更准确。

## 4. 第二阶段：重建评估指标

不先合成一个加权总分。每项报告分母、有效样本量、证据等级、缺失原因和可复现的错误实例。

### 4.1 ASR 内容

- 有可靠参考时，主指标采用日文字错率 CER，分别报告替换、删除、插入。CER 可以超过 100%，不可截断为看似正常的“准确率”。
- 本轮没有听音真值时，真实 CER 标为不可用。若计算对上下文校对稿的编辑距离，必须标为“参考稿文本差异”，不用于宣称真实准确率或单独决定 ASR 胜负；可能修正、未决部分单列并报告占比。
- 原文指标与规范化指标并列；规范化仅处理经过验证的书写差异。保留否定、长音和有意义的重复，读音 CER 用于解释汉字/假名差异，不代替内容正确性。
- 使用有顺序约束的句组匹配，允许合理拆句/并句；显式记录未匹配参考及多余候选。不能无限扩窗、重复借用邻句来提高命中率。
- 单列已确认漏句、无语音时生成对白、重复循环、短回答和弱语音错误。非言语声音的字幕策略与语言识别分开评价。
- 同时保留并评估原始输出与流水线清洗结果，区分模型错误和后处理造成的误删。

### 4.2 时间轴与可读性

- 在核对过的边界上计算起止误差的中位数、P95 和平均绝对误差；报告可匹配覆盖率，未匹配语句不能悄悄消失。
- 测试固定偏移、逐步漂移、首尾漏句和全空字幕。存在已知源文件偏移时，同时保留原始与校正结果，不能通过自由拉伸掩盖对齐失败。
- 闪现、过长、重叠、阅读速度和换行作为显示健康指标，不当作识别准确率。真实语音时间与显示延长后的时间分开统计。
- VAD 仅产生“疑似语音未覆盖”线索；使用原音确认的缺口才计作漏句。

### 4.3 翻译语义与结构

- 第一轮给所有翻译器相同、已冻结的日文上下文校对稿及上下文，隔离翻译能力。另以同一窗口的原始 ASR 文字测试错误传播，保留校对稿作目标，不修改冻结参考。原稿探针不是重新跑音频的全流程验证，也不证明原音识别准确率；输入损坏未恢复与清楚日文译错分别记录。
- 逐次记录模型实际收到哪些背景，不把复核者看过的前后文自动视为模型已经收到。局部重点输入诊断中，裸短词缺少场景或主体线索时保留多种合理译法，不凭参考中文强判核心错误；完整上下文受控实验另列，不能将局部诊断写成已完成。
- 根据用户补充，正式翻译对照必须以连续多条对白为输入：通常优先完整问答及更多背景；至少三条只是结构门槛，不保证语义背景充分。窗口逐条校对，不能跳过中间未决句；缺少足够上下文或关键背景未决的样本重新选。完整窗口全部翻译，重点句单独评分，背景不用于凑困难成绩；不同模型的实际日文上下文必须一致，拆批重试也不得丢失背景。较长暂停不自动等于场景切换，以预先校对的窗口为准，不改生产默认的全片分段策略。
- 按严重程度记录否定反转、人物/主客体错误、漏译、添译、含义弱化或强化、术语不一致、语气与方言处理，以及普通措辞问题。每项附源文位置和理由。
- 背景不用于扩大重点分母，但背景里的关键否定、错误主体及短回答删除仍进入选型风险判断，不能因“不评分”而忽略。
- 成人场景重点检查原意、关系、指代、语气和术语是否保留，不能把“更露骨”或“更通顺”自动视为更准确。
- 自动模型评审只作辅助，必须提供可核对证据；同一候选不能担任自己的裁判。没有可靠人工确认的语义结论注明限制。
- 对候选的 JSON、源 cue ID、删条、并条、空值和重复 ID 做结构校验。合法结构不等于语义正确；疑似噪声删除也要复核。
- 时间轴由原始 cue 映射决定，不接受模型自行改写时间；显示换行与源字幕拆并分开处理。保留日文原文，不能以翻译器自动“修正”的源文反过来证明 ASR 正确。

### 4.4 报告与兼容性

- 区分缺文件、解析失败、合法空结果、任务失败、跳过和没有真值；不可统一表示成零错误或满分。
- 为报告增加 schema/评估器版本。旧字段的废弃或更名明确记录，避免原字段悄悄换含义；兼顾 CLI、Linux GUI 和后续 Windows 的消费者。
- 提供逐片、逐类别、汇总与逐错误清单；同时报告按视频等权和按有效字数汇总的结果。配对比较保持同一批样本，必要时按场景聚类估计不确定性；四部视频不足以证明广泛泛化。

## 5. 第三阶段：先验收评估器

在批量跑候选模型前完成以下检查：

1. 建立可控错误用例：删句、插入无依据对白、否定反转、主客体互换、乱序、重复循环、合法重复、同音异写、短回答、合理拆并句、字幕偏移两秒、首尾缺口、空字幕、文件缺失、错 ID 和缺 ID。
2. 验证各自对应的指标：插入和删除进入 CER；否定/关系错误进入语义复核；纯时间偏移恶化时间指标；合法拆并不误判为漏句；共同错误的模型输出不能自动晋升为真值。
3. 使用真实片段的上下文校对记录检查检测器；只有证据足够的标签才统计对应误报和漏报，并注明属于文本/结构检查。依赖原音确认的漏识别、幻觉与边界误差保留未验证状态，不编造全量误报/漏报率。构造用例全部通过，只证明代码行为符合预期，不证明真实场景评估已经准确。
4. 冻结规则、阈值、提示词和盲测清单后再跑模型对照；若根据盲测结果改规则，记录变更并另建未使用的验证样本。
5. 扩展现有 [benchmark 测试](../tests/test_subtitle_benchmark.py) 与 [质量报告测试](../tests/test_quality_report.py)，验证报告兼容性和失败状态；实现后运行相关测试及静态检查。

通过条件：确定性的结构/计数用例符合预期；文本错误或风险判断有可追踪证据；缺乏真值时不输出假准确率；可测项目的误报/漏报与未验证项目分别披露。满足这些条件后可以开展有限结论的模型对照，不必等待不存在的人工日语核对者；但不得据此宣称 ASR 真实质量排名。若仍会系统性偏袒某个输出风格，先修评估，不据此宣布候选胜出。

## 6. 第四阶段：候选模型对照

以下是用户选定的候选，不是已验证优于当前模型的推荐结论。执行前核验模型卡、许可证、具体 revision 和运行依赖，并锁定版本；模型卡自报成绩不作为本项目成绩。

| 任务 | 基线/候选 | 对照要求 |
| --- | --- | --- |
| ASR 基线 | 当前 anime 与当前 Qwen 配置 | 保存现行端到端结果；Qwen 微调收益另做同配置对照 |
| ASR 候选 A | [jaykwok/Qwen3-ASR-1.7B-JA-Anime-Galgame](https://huggingface.co/jaykwok/Qwen3-ASR-1.7B-JA-Anime-Galgame) | 尽量只换权重，与相同运行栈的原始 Qwen 比较 |
| ASR 候选 B | [hhim8826/qwen3-asr-lora-ja-anime-v3](https://huggingface.co/hhim8826/qwen3-asr-lora-ja-anime-v3) | 核验所需 HF 基座及 LoRA；增加相同 HF 运行栈、不加载 LoRA 的基线 |
| 翻译基线 | 当前 GalTransl 模型、量化与配置 | 固定日文输入和上下文，记录实际文件与参数 |

执行顺序：

1. 用开发集少量片段验证加载、输出、时间戳、显存和异常处理，不一开始跑四部全片。
2. ASR 保持输入音频、切片和对齐器一致；确需更换运行栈时增加对应基座对照，不把框架、解码和权重的收益混为一谈。另设作者建议解码配置的实验行，不能暗中替换基线参数。
3. 翻译以 ASMR Q4_K_M 作本次实用对照；Q8 已有小集记录，没有新的量化问题证据不重复跑。结论限定为实际量化文件，不将 Q4 的结果自动推广为 Q8 或所有硬件。
4. 冻结参考与配置后完成约 20 段实用对照，生成匿名错误清单再解析映射。已看过的开发样本不宣称新盲测。对重复／截断风险已明显增加的 LoRA 停止扩大测试；jaykwok 若改善不稳定则暂不接入，避免为得出排名反复补样。
5. 先依据这一批的关键含义、稳定性和成本给出不接入／可选试用／值得替换的建议。只有值得接入的候选才进行必要的 Linux CLI/GUI 适配；四部全片的稳定性与最终 ASS 检查留作默认切换或正式支持前的验证，不作为初步建议的前置条件。无原音真值的部分仍只报告自动风险线索。
6. 单独记录冷启动、预热后耗时、音频时长比、峰值显存、内存、失败与重试。固定硬件和并发，分清 ASR、翻译及全流程时间；速度与质量分别给结论。

如果候选只在特定类别改善，保留为可选配置；证据不足或严重错误增加时维持当前默认。是否切换默认，以盲测前确定的主要质量指标和严重错误容忍标准为依据，不能测试后挑有利指标。

## 7. 第五、六阶段：集成与 Windows 收尾

Linux 侧先确保 CLI 和 GUI 使用同一套评估定义、配置校验和错误状态；如果采用新模型，同步模型选择、依赖提示、进度、取消和输出路径行为。不得只改 CLI 而让 GUI 继续显示旧指标或不支持新模型。

Windows 放在评估和 Linux 选型完成之后：

- 验证 Windows CLI、源码 GUI 和绿色版 GUI 的依赖、模型路径、中文路径、GPU 推理和报告展示。
- 检查新依赖是否能打包、旧模型是否仍能使用、取消与失败是否正确释放进程和资源。
- 使用固定回归样本核对结构与语义差异，允许说明底层非确定性，不以必须逐字一致代替质量验收。
- 按 [GUI 测试计划](GUI_TEST_PLAN.md) 补充平台验收记录。未完成前明确标注 Windows 未验证，不承诺绿色版已兼容。
