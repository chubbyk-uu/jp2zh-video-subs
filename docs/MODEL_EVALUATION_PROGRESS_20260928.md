# 首轮试样与评估器改进

日期：2026-09-28。状态：Linux 首轮试样与模型对照完成；扩展集尚未开始，不是最终选型报告。

对应计划：[字幕质量评估改进与模型对照测试计划](MODEL_EVALUATION_PLAN.md)。公开记录仅使用 V01–V04；素材、路径、逐句文本、模型原始输出与弃用原因保存在被 Git 忽略的本地实验目录，不上传素材或字幕。

## 已完成的评估修正

- 新增共享评估核心：严格区分缺失、空、无效、部分损坏和有效字幕；序列编辑距离分别记录替换、插入、删除，保留短回答、长音、否定和重复。
- 用单调、单次使用的有序句组匹配支持合理拆句、并句；不再用前后大窗口或读音集合命中当作默认质量指标。句组对应仍是启发式，复杂歧义需复核；全片超出计算预算时明确返回不可评估。
- 分开报告文本差异、边界差异和结构风险；没有听音真值时真实 CER 为 `null`，未经核对的边界也不产生“时间轴准确率”。不生成加权质量总分。
- 公共质量报告覆盖音频首尾及全空输出；VAD 仅作风险提示。显示覆盖按区间并集计算，重叠时长单列，不再把重叠字幕相加成超过 100% 的覆盖。相邻翻译重复检查按源 cue ID 和起点对应，不再按日中数组位置直接配对；无法确认的对应单列。
- 默认 benchmark 改用证据明确的文本对照；旧共识算法仅显式兼容。质量报告的旧 JSON 召回字段仍保留并标记废弃，不能解释为准确率。
- 新实验保留输入、模型、配置、代码、运行环境摘要和原始输出。历史 Stage 6 的复用也要求来源与 SRT/raw 两份输出摘要匹配，拒绝未记录来源的旧缓存。
- GUI 使用同一质量报告入口，并增加“结构/风险检查不等于识别准确率”的三语言提示。Linux 国际化检查已纳入测试；Windows 运行验证尚未进行。

## 样本和证据

四部视频均完成媒体信息、摘要、现有字幕来源登记。先进行时间分层试抽，再按用户决定弃用关键词句无法确定、缺乏有效对白的重点区间，回到同一视频换选。保留完整问答及前后文，并记录选样理由。

当前冻结 10 段开发试样：V01/V02/V03/V04 分别为 3/2/3/2 段，共 45 条重点区间日文与中文参考语句。其中 42 条文字语境明确，3 条有完整修改证据的高把握文本修订。重点区间没有“可能修正”或“无法判断”的标准语句；背景初稿仍允许未决，但不纳入标准答案评分。

首轮时间抽样保留为开发记录；后续两轮共 15 个候选中弃用 5 个、入选 10 个。精选样本存在选择偏差，不能代表全片，也不能替代之后的保留测试集。方言等困难片段若无法确定关键含义，只作为压力测试记录，不猜写成标准答案。

所有参考都属于 `context_reviewed`：助手基于两套旧 ASR 及前后文审校，未直接听音核对，时间边界也未验证。参考在查看本轮候选输出前冻结，候选不能反向改写自己的参考。原稿来自基线，可能偏好基线输出；不得据参考接近程度宣布真实 ASR 排名。

| GalTransl 基线翻译 | 同样完成 10 段、45 条；使用现有生产 CLI 的提示、batch=8、context=6、缓存和重试逻辑；保留原始请求响应 |

HF/LoRA 配对计时仅包括加载与转写，不包括 VAD、对齐及其他流水线步骤。第一开发包 86 切片：原版约 34.2 秒，LoRA 约 89.1 秒；第二开发包 25 切片：约 13.9/21.2 秒。不是精选 10 段的独立测速，也不是用户全片速度预测。LoRA 在第一包有 3 个切片触及 256 token 上限并出现重复循环，这些切片位于弃用或背景区间，应单列压力测试风险，不能混入精选参考成绩。

文本对照显示候选存在得失：jaykwok 在否定纠正和场景词书写上有改善，也有把正常动词转成不合语境词组的回退；LoRA 有改正词形的例子，也有改变关键动作含义的例子。没有听音真值，不报告真实 CER 或总体胜负。候选整条字幕还可能跨越重点/背景边界，不能简单按时间截取整条后计算“重点区间 CER”来排名。

## 固定日文翻译对照

三组输出均完成助手逐句文本复核，总计 135 个源 cue 对照。三个运行各覆盖 45/45 个源 ID，无缺失、重复 ID、空值删除或并条；ASMR 两种量化的 JSON 均合法，模型时间声明也未发生不一致。这个结果只说明本次输出结构通过，不说明语义正确。时间始终取不可变源 ID，不信任模型改写时间。

评审依据为冻结日文、上下文与错误证据，不按中文参考逐字匹配。能够同时解释为不同正确译法的词、隐含主体不确定的情况仅标待复核，不计成确定核心错误。当前评审者知道模型来源，不是独立人工日语盲审；复核页面按片段打乱 A/B/C 只帮助后续阅读，不能追溯地把已知来源评审变成盲审。

| 运行 | 助手复核标记核心含义问题的 cue 数 | 示例类型 | 10 段逐片运行合计（不含加载） |
| --- | --- | --- | --- |
| 现有 GalTransl v3.7 | 3 / 45 | 方言愿望误为已完成动作；两次请求误作寒暄 | 约 3.4 秒 |
| ASMR v0.2 Q4_K_M | 4 / 45 | 等待主体颠倒；方言愿望误读；房型误作旅行；场景词误译 | 约 43.5 秒 |
| ASMR v0.2 Q8_0 | 4 / 45 | 前三类仍在；场景词含义恢复但无根据指定第一人称 | 约 42.7 秒 |

这些数量是这次上下文评审的错误清单，不是自动准确率或普适模型排名；一条 cue 可能有多个问题，只计一次。还单列局部遗漏、不自然表达和存在合理备选的待复核项，不合成总分。Q8 改善了 Q4 部分词义、语气和表达，但没有消除全部核心问题；GalTransl 在请求表达等方面也有明显错误，不能当作无误标准。

速度受协议影响：ASMR 采用原生 JSON/ID/毫秒协议并受 grammar 约束，本次每组生成约 1305–1306 token；GalTransl 使用较紧凑的批次纯文本协议。两者不能当作同提示、同生成量的纯权重速度对比。两组 ASMR 是相同协议下的量化对照，但仅单次试跑，不能据微小计时差判定 Q8 更快。GalTransl 的本次模型加载约 20.3 秒，ASMR 约 0.8/1.1 秒，模型位于不同存储且缓存状态不同，加载时间不用于选型。翻译显存峰值未做持续采样；Q4/Q8 在本机 16 GB GPU 上完成不等于所有显存或平台配置均兼容。

初步决定：保留现有默认模型。候选尚无足够证据支持替换；ASMR 的“成人/ASMR 专用”定位不等于本项目素材中更准确。扩展前需要冻结独立保留样本，并明确背景上下文、方言和多角色对话的评审策略，不针对这 10 段反复调参后再宣布胜出。

## 接入失败及处理

- 原有 Numba 缓存曾导致音频预处理段错误；保留失败记录，使用独立的新缓存目录后旧 Qwen 重跑成功。不归因于识别模型质量。
- 原生 HF 首次缺失 `chat_template.jinja`，属于下载白名单遗漏；补齐固定 revision 模板，并令基线/LoRA 使用相同 processor 后成功。
- ASMR Q4 初次默认聊天调用只返回推理过程，尚不能称为有效翻译。正式实验采用显式关闭思考的提示前缀及 JSON schema 约束，再做 ID 和语义复核。

## 工具和复现入口

- [prepare_evaluation_samples.py](../scripts/prepare_evaluation_samples.py)：从本地四视频配置抽样、提取上下文音频和记录输入摘要；配置与真实路径留在本地。
- [run_evaluation_asr.py](../scripts/run_evaluation_asr.py)：运行原有 anime/Qwen 或替换 Qwen 权重的试样，记录缓存来源、运行状态和 SRT/raw/分片摘要。
- [build_evaluation_packet.py](../scripts/build_evaluation_packet.py)、[freeze_evaluation_reference.py](../scripts/freeze_evaluation_reference.py)：整理原稿与证据，拒绝关键未决/空区间成为标准试样，冻结而不覆盖参考。
- [fetch_evaluation_models.py](../scripts/fetch_evaluation_models.py)：固定候选 revision，只下载推理文件并验摘要。
- [run_evaluation_hf_asr.py](../scripts/run_evaluation_hf_asr.py)、[align_evaluation_hf_asr.py](../scripts/align_evaluation_hf_asr.py)：在隔离的原生 Transformers 环境做 HF/LoRA 配对，再用原有环境进行对齐后处理。隔离环境为 Transformers 5.17.0、PEFT 0.21.0，共享本机 Torch 2.12.0+cu130；没有升级项目原有生产环境。
- [run_evaluation_translation.py](../scripts/run_evaluation_translation.py)：读取单份冻结参考或跨轮选样清单，保持固定日文，运行 GalTransl/ASMR 对照及结构校验。
- [build_translation_review.py](../scripts/build_translation_review.py)：要求三组输入日文相同、输出完整，生成本地匿名列对照页并另存私有映射及输入摘要。
- [evaluate_subtitles.py](../scripts/evaluate_subtitles.py)：证据明确的短片 SRT 对照，含 JSON 与本地 HTML；[用法](USAGE.md#单步运行)。

每个入口可使用 `python scripts/<脚本>.py --help` 查看参数。采样/模型实验工具目前只在 Linux 验证；不能据此声称已进入 Windows 绿色版支持范围。详细逐句材料及复核页在本地 `work/model-evaluation/`，不纳入 Git。
